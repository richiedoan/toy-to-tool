# Owner notes: context and evidence scope

Three agreed fixture tasks are sign in/list/read own notes, edit/read back own note text, and sign out with session invalidation. The source README defines owner-only list/read/write, plain-text notes <=1000 characters, valid Unicode/quotes, SQLite retention across process restarts and in-memory expiring sessions. Identities alice/alice-demo and bob/bob-demo are intentionally public disposable fixture accounts, not production credentials. Changes within the target app are authorized; UI, README, architecture and already-correct behavior are protected.

Accepted baseline is owner-notes-v2. The earlier v1 preflight could not import hashlib.scrypt on the host and is retained as calibration, not ownership evidence. Before an accepted new agent trial, the fixture password derivation was changed to available stdlib PBKDF2-HMAC-SHA256 (600000 iterations). The source references for that project choice are [Python hashlib key-derivation documentation](https://docs.python.org/3/library/hashlib.html#key-derivation) and [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), accessed 2026-10-28; no numbered ASVS requirement is claimed. The v2 source preserves the ownership flaws for independent discovery. Both archives and hashes are retained.

Source inspection: note listing already filters owner, SQL uses bound parameters, note UI uses textarea.value/textContent, and session cookies are HttpOnly/SameSite=Strict on documented localhost HTTP. The evaluator executed direct owner/cross-owner/anonymous reads and writes, independently read the victim record, checked owned Unicode/quote edits and rejected ownership-transfer fields, exercised real local logout/replay/expiry, and used the actual browser UI. Cookie values are omitted from evaluator results. All execution uses a clean temporary copy of the five declared fixture files, empty disposable data directory and a new process. Existing session design and controls are preserved; no production assurance is implied.

S02 impact is important in this bounded local, replaceable-data fixture; a real tenant-data exposure requires its own severity context. Direct cross-owner failures in before/results.json are real observed failures. After evidence replays both denied and allowed paths. S03/S04 claims are limited to the described execution paths/model. S01 complete sensitive-surface/history verification and S05 relevant CSRF/public-endpoint/abuse subcases remain unknown. S06 is deferred at Standard; other groups are outside this report.

The independent fresh CLI trial is separate from evaluator HTTP/Chrome evidence. It had the runnable original v2 app, self-contained skill and engine, no expected findings or hidden tests. Its sandbox restricted actual sockets/browser use; its source/handler observations are preserved under independent-agent. The first packet relocated the fixture relative to README commands; this exporter defect is not an app startup finding. Future packets preserve fixtures/<name>/ paths. One such trial does not establish skill effectiveness.
